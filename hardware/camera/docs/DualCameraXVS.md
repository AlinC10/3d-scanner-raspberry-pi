# DualCameraXVS Class

The `DualCameraXVS` class (`dual_camera_xvs.py`) provides an interface to control two Arducam IMX477 cameras simultaneously using true hardware synchronization over an XVS cable connection.

## Hardware & OS Prerequisites

Before using this class, you **must** configure your hardware:
1. Connect the XVS pins between the two cameras using a jumper wire.
2. Update your `/boot/firmware/config.txt` to assign the Master (source) and Slave (sink) roles. For example:
   ```ini
   dtoverlay=imx477,camera0,xvs_source
   dtoverlay=imx477,camera1,xvs_sink
   ```

## Class Overview

This class works similarly to the standard `DualCamera` class but makes one fundamental change: **The Startup Sequence**.

In XVS mode, the Slave camera is fully reliant on the timing pulses generated by the Master camera. If the Slave is started, it will permanently freeze and wait for the Master to begin. Therefore, the `DualCameraXVS` class strictly enforces the order of operations when invoking the `picamera2` engine:
1. The Slave's start thread is dispatched first.
2. The code applies a small 0.1-second delay.
3. The Master's start thread is dispatched, generating the hardware pulse that unblocks the Slave and synchronizes their exposures down to the microsecond.

*Note: Without this threaded sequence, launching an XVS Slave camera in Python would result in a permanent script deadlock.*

## Setup & Initialization

### `__init__(self, master_id=0, slave_id=1, quality=95, size=None, video_size=None, preview_size=None, master_rotation=0, slave_rotation=0)`
Initializes the dual camera setup, assigning `master` and `slave` properties. By default, it expects the Master on CSI port 0 and the Slave on CSI port 1.

## Concurrent Operations

Just like the software-synced `DualCamera`, all commands are executed concurrently, with tuples accepted for specific independent overrides:

* **`prepare_scan(self, **kwargs)`**: Prepares and locks both cameras for scanning. The Slave starts before the Master. You can pass independent focuses, e.g., `focus=(300, 500)`.
* **`focus_set(self, position)`**: Actuates VCMs to absolute positions. Accepts an `int` or a `Tuple[int, int]` (Master, Slave).
* **`focus_step(self, delta)`**: Adjusts VCM focuses relatively. Accepts an `int` or a `Tuple[int, int]`.
* **`capture_photo(self, output_prefix="photo", output_dir=".", meshroom_rig=True, ...)`**: Captures hardware-synchronized photos. Like the standard dual class, setting `meshroom_rig=True` outputs photos to `output_dir/0/` and `output_dir/1/` with identical filenames for Meshroom rig constraint detection.

## Lifecycle Management

* **`close(self)`**: Gracefully shuts down the thread pool and closes both cameras. Supported via `with` context management.
